SAFE CHANGE WORKFLOW
  A. Capture the current working result.
  B. Read the complete relevant HTML/CSS/JS files.
  C. Search duplicate selectors/functions/queries and dynamic states.
  D. Cross-check at least twice, preferably three times.
  E. Change one responsibility at a time.
  F. Validate JS syntax and local asset references.
  G. Test desktop and mobile behavior.
  H. Only then commit and push.

DO NOT
  - Add another !important or FINAL OVERRIDE before finding the original cascade cause.
  - Add another Supabase query when the same data already exists in the page controller snapshot.
  - Add polling when an existing event can signal completion.
  - Add MutationObserver when explicit state/event flow can do the same job.
  - Put secrets in public JavaScript.
  - Remove backend RPC/RLS/FK/Storage policies without dependency review.

PERFORMANCE PRINCIPLE
  Prioritize changes that reduce actual work:
    network requests
    repeated DOM rendering
    observers/timers/polling
    unnecessary eager image loading
    oversized assets
  Do not optimize merely to reduce line count.
